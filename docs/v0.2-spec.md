## 1. What we are building (one sentence)

Replace the dropdown price-lookup at `/[locale]/tool` with a **single-button proposal flow**: the freelancer pastes a client's brief, Rizq extracts the scope, computes a price from market data weighted by the freelancer's profile, asks 1–3 bilingual follow-ups only when a price-critical field is uncertain, and produces a **Rizq-stamped bilingual proposal artifact** (web page + PDF + WhatsApp summary) the freelancer sends to their client.

The price and the proposal are one deliverable. Neither ships without the other.

---

## 2. In scope / out of scope

**In scope (v0.2):**
- Brief-paste intake (text; optional image/PDF upload deferred — see out of scope)
- LLM scope extraction (DeepSeek) → structured scope object with per-field confidence
- Rule-based bilingual follow-up questions for low-confidence price-critical fields
- Price computation: existing statistical core (`benchmark_records`) + freelancer-profile weighting
- Bilingual proposal artifact: web page at `/[locale]/p/[id]`, downloadable PDF, WhatsApp text summary
- Rizq verification stamp on the artifact + methodology link
- Onboarding upgrade: brand block (name, logo, contact, defaults)
- Quota migration: unit-of-value becomes the **proposal**; statistical preview stays for anonymous
- Telemetry: the moat-validation events (non-negotiable, ships with v0.2)

**Out of scope (deferred — do not build in v0.2):**
- Voice-note ingestion (v0.4)
- Image/PDF/screenshot brief upload (v0.3 — text paste only in v0.2)
- Outcome tracking UI / win-loss dashboards (v0.3 — capture nothing yet beyond view events)
- Per-freelancer Bayesian / embedding model (post-v0.3 — v0.2 uses the existing statistical core)
- Fanar/Jais integration (only if post-ship telemetry shows a DeepSeek dialect problem)
- KYC / buyer-registry enrichment (v0.5)
- Buyer-side surface (v0.6)
- pgvector / similarity search (not needed — v0.2 has no embeddings)

## 3. The user flow

### 3.1 Anonymous visitor (unchanged value, SEO + funnel)
- Lands on `/[locale]/tool`. Sees the **statistical preview**: the existing specialty/city/tier dropdowns → price band. No artifact. 1 lifetime preview (existing cookie quota).
- CTA: "Sign up to turn this into a client-ready proposal."

### 3.2 Authenticated freelancer (the new flow)
1. Lands on `/[locale]/tool`. Sees a single large textarea: *"ألصق رسالة العميل هنا"* / *"Paste the client's message here"*.
2. Pastes the brief. Taps **«أنشئ العرض»** / **"Generate the proposal"**.
3. Loading state (skeleton). Server action:
   - Calls DeepSeek to extract the scope object (with per-field confidence).
   - Computes the price via the statistical core, weighted by the freelancer's profile.
4. If 1–3 price-critical fields are below the confidence threshold, an inline bilingual question step appears. Freelancer answers or skips (skip → wider band, proceed).
5. The **artifact** renders: branding, scope, price band + anchor, halal milestones, provenance line, Rizq stamp, terms.
6. Freelancer can edit any block inline, then:
   - **Download PDF**
   - **Copy share link** (`/[locale]/p/[id]`, view-tracked)
   - **Send via WhatsApp** (pre-formatted text summary)
7. Saved to dashboard as a proposal — re-openable, duplicable for similar future gigs.

## 4. Components

| # | Component | What it does | Key dependency |
|---|---|---|---|
| C1 | **Scope extractor** | `extractScope(briefText, locale)` → `Scope` via DeepSeek + Vercel AI SDK `generateObject` against a Zod schema. Returns per-field confidence. | DeepSeek API key (in hand), AI SDK |
| C2 | **Follow-up engine** | Pure function: given `Scope`, returns ≤3 bilingual questions for price-critical fields where confidence < threshold. Hand-authored templates. | None (rules + i18n strings) |
| C3 | **Price computer** | Wraps the existing statistical core (`benchmark_records` aggregation, the logic behind today's `calculate.ts`). Inputs derived from `Scope` + freelancer profile. Outputs band + anchor + sample size + fallback flag. | Existing `benchmark_records`, `calculate` logic |
| C4 | **Artifact renderer** | Bilingual proposal → React component → (a) web page, (b) PDF. Branding from profile. Rizq stamp + methodology link baked in. | PDF lib (see §7), profile brand block |
| C5 | **Public proposal route** | `/[locale]/p/[id]` server component; renders the saved artifact read-only; logs a view event. RLS: only shareable proposals are publicly selectable. | `proposals` + `proposal_events` tables |
| C6 | **Onboarding brand block** | Adds brand fields to onboarding + profile settings. Drives C4. | `users` table columns (§5) |
| C7 | **Quota migration** | Unit becomes the proposal. Anonymous = preview only. Free = N proposals/month. Pro = more + branding. | `users` quota columns (§5) |
| C8 | **Telemetry** | Emits the moat-validation events. Non-negotiable, ships with v0.2. | PostHog (already wired) |

## 5. Data model changes (grounded in live schema)

Existing relevant tables: `users` (profile 1:1 auth), `queries` (preview log + quota + `/r/[id]`), `benchmark_records` (361 rows, the price dataset), `specialties`/`cities`/`experience_tiers` (ref), `pricing_submissions` (crowd data).

### 5.1 New table: `public.proposals`
```
id                uuid pk default gen_random_uuid()
user_id           uuid  → auth.users.id   (not null)
brief_text        text  (the pasted input; PII-bearing — see §10)
scope_json        jsonb (the extracted Scope object incl. confidences)
specialty_id      uuid  → specialties.id  (resolved from scope)
city_id           uuid  → cities.id       (from profile/scope)
experience_tier_id uuid → experience_tiers.id (from profile)
price_min         numeric
price_anchor      numeric
price_max         numeric
sample_size       integer
fallback_used     boolean default false
currency          text default 'SAR'
status            enum proposal_status ['draft','final']  default 'draft'
public_share      boolean default false
share_token       text unique  (random; used in /p/[id] for unguessable links)
created_at        timestamptz default now()
updated_at        timestamptz default now()
```
RLS: owner can CRUD own rows; anyone can SELECT a row where `public_share = true` (mirrors the existing `queries.public_share` pattern).

### 5.2 New table: `public.proposal_events`
```
id           uuid pk default gen_random_uuid()
proposal_id  uuid → proposals.id (not null)
event_type   enum proposal_event ['viewed','pdf_downloaded','link_copied','whatsapp_opened']
viewer_is_owner boolean default false   (distinguishes freelancer self-view from buyer view)
created_at   timestamptz default now()
```
RLS: insert allowed from server on public route; SELECT restricted to the proposal owner. **This table is how the moat hypothesis becomes measurable** (§9.1 of research doc).

### 5.3 `public.users` — add brand block columns
```
brand_name          text null
logo_url            text null   (Supabase storage path, signed-URL access)
contact_email       text null
contact_phone       text null
contact_whatsapp    text null
tagline_ar          text null
default_deposit_pct integer default 50   (halal milestone default)
default_revisions   integer default 2
default_ip_terms    text default 'full_transfer'  ('full_transfer'|'license'|'per_project')
proposal_count_this_month integer default 0   (new quota counter; queries counter stays for previews)
```

### 5.4 New storage bucket: `proposal-artifacts`
Private bucket, signed-URL access (same pattern as the existing `submission-proofs` bucket). Stores generated PDF blobs and uploaded logos.

### 5.5 New enums
`proposal_status` (`draft`, `final`), `proposal_event` (`viewed`, `pdf_downloaded`, `link_copied`, `whatsapp_opened`).

**No pgvector. No embeddings. No new RPC for pricing** — C3 reuses the existing statistical aggregation.

## 6. The scope schema (v1 — will iterate)

```ts
const ScopeSchema = z.object({
  specialty: z.enum(SPECIALTY_SLUGS),                 // mapped to specialties.slug
  deliverables: z.array(z.string()),                  // free-form, human-readable
  deliverable_count: z.number().int().nullable(),
  revisions: z.number().int().nullable(),
  urgency: z.enum(["rush_under_1_week","standard_1_4_weeks","long_term"]).nullable(),
  complexity_signals: z.array(z.string()),
  client_type: z.enum(["individual","smb","corporate","government","agency"]).nullable(),
  geography_target: z.enum(["ksa_local","gcc","international"]).nullable(),
  language_preference: z.enum(["ar","en","both"]).nullable(),
  budget_mentioned: z.number().nullable(),            // SAR if the client named one
  ip_transfer: z.enum(["full_transfer","license","unclear"]).nullable(),
  field_confidence: z.record(z.string(), z.number()), // 0..1 per field above
});
```
Price-critical fields that trigger follow-ups when `field_confidence < 0.7`: `deliverable_count`, `revisions`, `urgency`, `client_type`, `ip_transfer`. Max 3 questions surfaced per session, ranked by price impact.

## 7. Tech decisions

**Locked:**
- LLM: **DeepSeek** via **Vercel AI SDK** (`generateObject`, AI SDK v6). No Fanar/Jais unless telemetry forces it.
- Pricing: reuse the existing statistical core. No new model.
- Storage: new private Supabase bucket, signed URLs.
- Analytics: existing PostHog wiring.

**To evaluate during build (engineering-lead call, will report):**
- PDF generation: lean toward **`@react-pdf/renderer`** for clean Arabic/RTL typography in a serverless function; alternative is HTML→PDF (Playwright/Browserless). Decision recorded once prototyped.
- Whether the follow-up step is a second server round-trip or streamed in the first response (UX vs. complexity tradeoff).

**Dependency to add:** `ai` + the DeepSeek provider for the AI SDK, and the PDF library. These are new `package.json` deps — flagged here per the "tell me before installing deps" standing rule. **Approve dep additions as part of approving this spec, or call them out.**

## 8. Acceptance criteria (definition of done)

v0.2 is done when **all** are true:
1. An authenticated freelancer pastes a real Arabic/dialect WhatsApp brief and gets a usable proposal artifact in one short interaction.
2. The artifact renders correctly bilingually on mobile (70%+ of KSA traffic), RTL-correct.
3. PDF download, share link, and WhatsApp summary all work end-to-end.
4. `/[locale]/p/[id]` renders read-only for a shared proposal and logs a `viewed` event distinguishing buyer vs. owner.
5. Anonymous statistical preview still works at `/[locale]/tool` (SEO + funnel intact).
6. Onboarding captures the brand block; existing users are routed to fill it once before first proposal.
7. Quota enforces the new proposal unit; previews remain separately metered.
8. Telemetry emits `proposal_generated`, `followup_answered`, `followup_skipped`, `artifact_downloaded`, `artifact_shared`, `artifact_viewed_by_buyer` — verifiable in PostHog.
9. `pnpm build` clean, existing 13 tests still green, new logic (scope→price mapping, follow-up selection, quota) unit-tested.

## 10. Risks specific to this build

| Risk | Mitigation |
|---|---|
| DeepSeek dialect extraction weak | The follow-up loop is the safety net; extraction only needs honest confidence, not perfection (accepted risk, research §9.1) |
| Brief text contains client PII | Store `brief_text` with restricted RLS; add per-user delete; document retention in privacy policy before public launch |
| PDF Arabic typography breaks | Prototype `@react-pdf/renderer` with Tajawal early; fallback HTML→PDF if needed |
| Moat unproven | Telemetry ships with v0.2 — this is why C8 is non-negotiable (research §9.1) |
| Scope creep into v0.3+ features | This spec's §2 out-of-scope list is the contract; anything past it is a new spec |
